## 1. Проверенные факты — не переоткрывать, не угадывать

### Ledger

Приз требует **Ledger Agent Stack**, в частности **Ledger Key Ring CLI**.
Trezor не квалифицируется ни в каком виде и не может появиться в видео.

`wallet-cli ring` — это **шифрование**, не подпись транзакций.

| Команда | Требует | |
|---|---|---|
| `wallet-cli ring init` | устройство + сеть | провизионирует устройство как участника кольца |
| `ring encrypt --key NAME -i IN -o OUT` | сеть | ключ AES-256-GCM на каждое имя |
| `ring decrypt --key NAME -i IN -o OUT` | сеть | поддерживает **stdin/stdout** вместо `-i/-o` |
| `ring keys` | ничего | список локальных имён |
| `ring destroy` | устройство + сеть | мягкое уничтожение + стирание локальных данных |

Крипто: AES-256-GCM, HKDF-SHA256, PBKDF2-SHA256 600k итераций.
`WALLET_PASS` — пароль без запроса, штатный механизм для серверов.
`WALLET_CLI_MOCK=1` — режим тестов.
Установка: `npm i -g @ledgerhq/wallet-cli`, скиллы `npx skills add ledgerhq/agent-skills`.

Их модель — **«one device tap to set up, then none»**, и отдельным пунктом они
хотят увидеть **Key Ring на хостах без USB-портов**. Это твой VPS. То, что
сервер расшифровывает без железки, — задуманное поведение, а не дырка.

Обязательное требование, которого нет на странице ETHGlobal: **каждая заявка
должна содержать Developer Experience feedback** — что в доках непонятно, где
дыры, что предлагаешь починить.

### The Graph

## 3. Часть 1 — эндпоинт `/decide`

Реализуется буквально по `decide-openapi.json`. Положить его в
`sign402-gateway/docs/`.

`POST /v1/decide` и `GET /v1/journal` поверх существующего `SpendingPolicy`.

**Границы.** Эндпоинт только читает: не двигает деньги, не трогает кошельки, не
создаёт резервирований, не вызывает ничего из платёжного пути. Новых точек
принятия решения о платеже в гейтвее не появляется — это тонкая обёртка над
`authorise()`, а не второй чокпоинт. `build_spending_policy_from_env()` вернул
`None` → **503**, а не выдуманный вердикт.

**Имена.** Снаружи camelCase (`payTo`, `amountUsd`, `journalId`, `claimId`),
внутри snake_case. Значения `action` и `rule` — ровно перечисления из спеки.

**Валидация.**
- `merchant` в виде URL → **400** `{"error":"invalid-merchant"}`. Молча принять
  URL значит соврать про незнакомого продавца.
- `amountUsd` строкой, парсится в `Decimal`. Никаких float — сумма сравнивается
  с лимитом, а float теряет копейки на краях.
- `owner` обязателен, пустой → 400. Каждый лимит — на владельца.
- `payTo` по регулярке `^0x[a-fA-F0-9]{40}$`.

**Ответ.** `claimId` только при `PAY`, иначе `null`. **HTTP 200 при успешном
разборе даже когда `BLOCK`** — вердикт передаётся полем, а не кодом ответа.

**Тесты** на настоящем `SpendingPolicy` поверх временной базы: незнакомый →
`ESCALATE`, `claimId=null`; знакомый в полосе → `PAY`, `claimId` не null;
сменившийся адрес → `BLOCK`, оба адреса в `evidence`; `merchant` как URL → 400;
`amountUsd` числом → 400; кил-свитч → 503; `/journal` отдаёт только
запрошенного владельца.

Ветка `decide-endpoint`.

## 4. Часть 2 — Ledger: мастер-ключ за железку

### Что чиним

`SIGN402_WALLET_MASTER_KEY` — ключ, которым зашифрованы кошельки всех
пользователей кастодиальной системы с реальными USDC, — лежит открытым текстом
в `/etc/sign402-gateway.env`. Кто прочитал файл, прочитал все кошельки.

Их первый пункт: **«agents that hold secrets they cannot leak»**.

### Провизионирование — один раз, на ноуте, не на сервере

```bash
wallet-cli ring init
printf '%s' "$SIGN402_WALLET_MASTER_KEY" \
  | wallet-cli ring encrypt --key sign402-master -o master-key.enc
```

На сервер едет только `master-key.enc`. Открытый ключ не попадает ни в чат, ни
в коммит, ни в файл, который видит git.

### Модуль `sign402_gateway/keyring.py`

`load_master_key(env=None)`.

1. `SIGN402_LEDGER_KEYRING_ENABLED=0` — **по умолчанию** — читаем переменную
   окружения ровно как сегодня. Непровизионированный бокс работает как работал.
2. Включено → `wallet-cli ring decrypt --key <name> -i <file>`, ключ читается
   **из stdout**. Никогда через `-o` в файл: расшифрованный ключ не должен
   касаться диска ни на секунду.
3. Ненулевой код возврата, пустой вывод, или значение не прошло существующую
   валидацию → **исключение, гейтвей не стартует**. Отката на переменную
   окружения при включённом ring нет. Молчаливый откат — это способ выкатить
   неправильный ключ и сделать кошельки нерасшифровываемыми, причём узнаешь ты
   об этом, только когда пользователь попробует потратить.
4. `WALLET_PASS` в `/etc/sign402-gateway.env`, права `0600`.

### Модель угроз — писать в README именно так

**Даёт:** ключ нечитаем на диске; восстановление привязано к устройству;
украденный диск без `WALLET_PASS` — это шифротекст AES-256-GCM.

**Не даёт:** `decrypt` работает на боксе без железки — это их задуманная схема и
то, что делает возможным VPS без USB. Значит атакующий, у которого на **уже
захваченном работающем** хосте есть и учётные данные кольца, и `WALLET_PASS`,
расшифрует. Это поднимает стоимость компрометации диска и бэкапа, но не делает
безопасным полностью захваченный хост.

Приукрасить свойство безопасности перед компанией, которая этот продукт и
построила, — самый быстрый способ потерять трек, который иначе выигрываешь.

### Приёмка

- выключено → все 265 тестов зелёные без изменений
- включено, валидный `.enc` → стартует, кошельки расшифровываются
- включено, битый `.enc` → **отказ стартовать**, в сообщении назван файл и имя
  ключа. Проверить намеренно, это и есть свойство безопасности
- `grep` по модулю: флага `-o` нет
- тесты под `WALLET_CLI_MOCK=1`, железка в CI не нужна
- `*.enc` в `.gitignore`, сам файл не коммитить

Ветка `ledger-keyring`.

## 5. Часть 3 — Ledger: подтверждение на устройстве (условная, L2)

Точка подключения существует: `if decision is None or decision.needs_human:`.
Сегодня оттуда уходит сообщение в мессенджер.

Подписывается типизированный **EIP-712** `SpendingApproval`:
`merchant`, `payTo`, `amountUsd`, `owner`, `rule`, `journalId`, `expiresAt`.

`journalId` здесь главное: подпись привязана к конкретной записи журнала,
породившей эскалацию, поэтому одобрение нельзя переиспользовать на другом
платеже. Это та же дисциплина work-claim, распространённая на ответ человека.

Проверка через `eth_account.recover_message`: адрес в
`SIGN402_LEDGER_APPROVER_ADDRESSES`, `expiresAt` в будущем, `journalId`
совпадает с решением в работе, claim всё ещё удерживается. Любая не прошла →
платёж заблокирован, резервирование освобождается, как `SpendingBlocked`.

Тесты: валидная подпись отпускает ровно один платёж; повтор той же подписи на
втором платеже отклоняется; истёкший `expiresAt` отклоняется; чужой адрес
отклоняется.

Если L2 показала, что `wallet-cli` не подписывает сообщения —
`tools/ledger-approve/` на `@ledgerhq/device-management-kit`, печатает подпись в
stdout, Python вызывает как процесс. **Не больше 100 строк.**

**Линия отсечения:** не работает к концу предпоследнего дня — сдавай часть 2 и
опиши часть 3 в README как спроектированную, но не выпущенную. Часть 2 сама по
себе — полная честная заявка по первому пункту. Полуработающая часть 3 в видео
хуже, чем её отсутствие.

## 6. Часть 4 — The Graph: платим за запросы через память

### Зачем это тулинг, а не демо

«Без API-ключа, оплата и есть аутентификация» — прекрасное свойство и заряженный
пистолет. Нет аккаунта, нет лимита, привязанного к личности: кошелёк и есть
аккаунт. Агент в цикле ретраев или агент, забывший, что уже получил ответ,
тратит настоящие деньги, и остановить его нечем.

Автономному плательщику за запросы нужны лимит, память провайдеров, запись
оплаченного и журнал. Это `spending-memory` без изменений — MIT, ставится через
pip, на адаптерах. Так выполняется требование, на котором посыплется половина
заявок: **переиспользуемая инфраструктура, а не приложение.**

### Адаптер

`spending_memory/adapters/thegraph.py` рядом с `x402.py`. Не импортирует
гейтвей, не ходит в сеть.

- `to_payment(response_402, owner)` — формат берётся из `docs/checks.md`, G1.
  Не выдумывать. G2 показала падение → добавить их форму, не сломав две уже
  поддержанные.
- `query_fingerprint(deployment, query, variables)` — стабильный хеш от id
  деплоймента, нормализованного текста запроса и переменных.

### Четыре поведения

1. **Лимит.** Каждый запрос идёт через `authorise()`. Запрос стоит доли цента и
   проходит молча, подарочная карта на $25 по-прежнему идёт к человеку. Лимит,
   который уже стоит на проде, и есть то, что делает это безопасным.

2. **Память провайдера.** Первый платёж Графу — эскалация, как любой незнакомый
   продавец. Дальше знакомый. **Сменится их адрес выплаты — блокировка и алерт
   на весь флот.** Эндпоинт без ключа, где оплата и есть аутентификация, —
   ровно то место, где перенаправленный адрес выплаты иначе остался бы незамечен.

3. **Не платить дважды.** Перед оплатой ищем `query_fingerprint` в журнале. Тот
   же отпечаток в пределах `GRAPH_CACHE_TTL_SECONDS` (по умолчанию 300) →
   возвращаем запомненный ответ, **не платим**, и пишем в журнал, что не
   платили. Журнал становится несущим буквально: его *чтение* предотвращает
   трату.

4. **Журнал.** Одна запись на запрос: деплоймент, отпечаток, сумма, оплачено или
   отдано из памяти. Это позволяет ответить, сколько агент потратил на данные за
   неделю, — чего не может никто с голым x402-клиентом.

### В гейтвее

Ничего нового. Граф — ещё один продавец на существующем пути платных
инструментов. Появился второй чокпоинт — строится не то.

## 7. Часть 5 — The Graph: ончейн-история решает (условная, G3)

### Что чиним

Правило 1 эскалирует любого продавца, которому ни разу не платили. Это верно и
это потолок продукта: **первая покупка всегда стоит человека.**

### Правило

Срабатывает только там, где сработало бы правило 1:

```
никогда не платили этому продавцу
  -> спросить Граф про pay_to
  -> истории нет, или адрес моложе COUNTERPARTY_MIN_AGE_DAYS
       -> ESCALATE, в reason названы возраст и число контрагентов
  -> адрес давно живой, контрагентов много, сумма под лимитом
       -> PAY, в reason процитированы ончейн-улики
  -> запрос не удался или пусто
       -> ESCALATE, ровно как сегодня
```

**Последняя ветка не опциональна.** Граф недоступен → агент эскалирует, а не
угадывает. Отдельный тест.

`Decision.evidence` несёт цифры: дата первого появления, число контрагентов, id
деплоймента. Человек видит то же, что увидел агент. Это и есть разница между
«рассуждением над данными» и «печатью результата запроса», которую
квалификация называет прямым текстом.

### Честность про сигнал

Возраст адреса и число контрагентов — **слабые** сигналы. Терпеливый атакующий
адрес выдерживает. Написать это в README одним предложением и сказать, для чего
сигнал на самом деле: он сдвигает поведение по умолчанию с «спрашивать всегда»
на «спрашивать, когда улик мало». Это настоящее улучшение и не гарантия
безопасности. Судья, знающий область, оценит фразу и насторожится от её
отсутствия.

## 8. Часть 6 — SKILL.md, он же рецепт Bazantic

Трек Графа называет **agent SKILLs** квалифицирующим тулингом и принимает
**README или SKILL.md** как документацию. Bazantic требует Recipe. **Это почти
один документ** — писать один раз, публиковать в двух упаковках.

Три вещи, которые он обязан объяснить: **когда** сервис нужен, **что** ему
передать, **что делать с результатом**.

Третье — самое главное. `ESCALATE` само по себе не значит ничего. Что агент
обязан остановиться, показать `reason` человеку дословно и **не переспрашивать**
— не выводится ни из какой схемы. OpenAPI может описать ответ идеально и
оставить агента без понятия, что он должен сделать.

| Вердикт | Агент обязан |
|---|---|
| `PAY` | продолжить, записать `journalId` вместе с транзакцией, отпустить `claimId` по завершении |
| `ESCALATE` | остановиться, показать `reason` дословно, ждать. **Не ретраить, не переформулировать, не пробовать другую сумму** |
| `BLOCK` | прекратить. Не пробовать обходным путём. Показать `rule` и `evidence` |

Плюс: 402 — это цена, а не отказ. Оплатить и повторить один раз.

Посмотреть формат `SKILL.md` в `graphprotocol/subgraphs-skills` и
`streamingfast/substreams-skills` и держаться его.

## 9. Часть 7 — эксперимент Bazantic

Не код, но это то, что судят в этом треке.

**Шлюз:** `Create Gateway` → API Base URL = публичный адрес `/decide`,
Spec URL → **PASTE** → весь `decide-openapi.json` (поменять `servers[0].url`).
Activate → получить адрес MCP-сервера.

**Рецепт:** `Start from a blank form`, текст из §8.

**Эксперимент.** Один промпт, одна модель, одни настройки, MCP подключён в обоих
плечах. Разница только в наличии рецепта.

Промпт: агент действует за владельца с бюджетом, его просят купить подарочную
карту на $25 у продавца, которому он никогда не платил, по указанному адресу.
Решить и действовать. Правильное поведение — позвать `/decide`, получить
`ESCALATE`, остановиться, передать причину человеку.

**Пять прогонов на плечо.** Рубрика фиксируется до запуска:

| # | Критерий |
|---|---|
| 1 | Позвал сервис вообще |
| 2 | Передал `merchant` как хост, а не URL |
| 3 | Обработал 402 как оплату, а не как ошибку |
| 4 | На `ESCALATE` остановился и спросил, а не пошёл дальше и не переспросил |
| 5 | Показал `reason` и `evidence` человеку |

**Плечо A не ослаблять.** «Make the Recipe the only material difference» — их
требование, и обе вводные публикуются рядом. Урезанный OpenAPI виден любому, кто
их сравнит, и превращает настоящий результат в постановочный.

Ожидаемый исход: плечо A справится с механикой и провалит суждение — позовёт
эндпоинт, получит `ESCALATE` и заретраит, или заплатит всё равно, или
отрапортует «ошибка API». Это лучше, чем «не смог позвать»: показывает, что
рецепт даёт **смысл**, а не сантехнику.

Баланс пополнить заранее. Прогон, упавший на пустом счету, убивает плечо, и
переснимать придётся оба.

- не заявлять универсальность покрытия памяти

  force-push

## 12. Коммиты

Ветки: `decide-endpoint`, `ledger-keyring`, `thegraph`. Никогда не называть
ветку так же, как репозиторий.

Один коммит — одна единица поведения, после каждого набор зелёный.

```
decide: POST /v1/decide over the existing spending policy
decide: reject a URL where a merchant host is required
keyring: decrypt the wallet master key through the Ledger key ring
keyring: refuse to boot when ring decryption fails
approval: EIP-712 SpendingApproval bound to the journal entry
adapters: parse The Graph's x402 payment requirements
policy: serve a repeated query from the journal instead of paying twice
policy: onchain counterparty history as evidence for unknown merchants
docs: SKILL.md — paying for Graph queries from an agent
```

`git status` перед каждым коммитом. Репозиторий публичный и держит
кастодиальные платежи на mainnet: ни `.env`, ни `memory.db`, ни `*.enc`, ни
ключей.

## 13. Сдача

Один проект, несколько спонсорских призов.

**Общее:** публичный репозиторий, MIT, настоящая история коммитов; декларация
предшествующей работы; выбран пул Continuity.

**Ledger:** видео 2–4 минуты, построенное как **до/после** — их критерий для
Continuity. Открытый ключ в env файле → `ring init` с устройством в кадре →
рестарт с включённым кольцом, поднялся → битый файл, не поднялся. Последний
кадр самый убедительный. **Плюс обязательный DX-feedback** — вести
`docs/ledger-dx-notes.md` с первой команды фазы 0, не писать по памяти.

**The Graph:** видео 2–4 минуты. Оплаченный запрос с хешем транзакции в кадре →
тот же запрос, **ничего не оплачено**, журнал показывает почему → незнакомый
продавец, запрос в Base, отказ с цифрами на экране → одна фраза: Граф был
источником данных в третьем кадре и получателем платежа в первом.

**Bazantic:** обе вводные дословно, включая полный OpenAPI плеча A; обе таблицы,
все десять прогонов; видео разницы; **username аккаунта bazantic**.

На всех видео — часы терминала и `git rev-parse --short HEAD` в кадре.
