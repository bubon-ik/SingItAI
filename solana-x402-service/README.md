# SingIt Solana — Venice x402

Отдельный клиент для оплаты Venice в USDC на **Solana mainnet**. Первый этап расширения SingIt на Solana. Существующий проект `Berlin Hack` не изменяется.

Клиент умеет создать отдельный кошелёк, войти в Venice через Solana SIWX/Ed25519, прочитать балансы, получить котировку пополнения, провести явно одобренный платёж и запросить ответ модели. Venice зачисляет пополнение на свой баланс и затем списывает стоимость запросов с этого баланса.

## Установка

Нужен Node.js **24+**. Используется встроенная SQLite; Node может печатать предупреждение об экспериментальном статусе этого модуля.

```sh
npm ci --ignore-scripts
npm test
npm start -- --help
```

Версии SDK закреплены в `package.json` и `package-lock.json`. Публичный RPC используется по умолчанию; при ограничениях задайте `SOLANA_RPC_URL` для своего mainnet RPC.

## Первый запуск

```sh
npm start -- wallet-init
npm start -- wallet
npm start -- balance
npm start -- quote
```

`wallet-init` создаёт **новый** кошелёк в `.local/wallet.json` с правами `0600`; существующий файл никогда не перезаписывается. Для существующего кошелька можно указать `SOLANA_KEYPAIR_FILE` либо передать 64-байтный keypair в base58 через переменную `SOLANA_PRIVATE_KEY`. Приватные ключи не передаются аргументами командной строки. `.env` автоматически не загружается.

Пополнять нужно **показанный адрес кошелька** нативным USDC в сети Solana. Mint USDC: `EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v`. Проверка баланса учитывает USDC в associated token account, из которого платит SDK. Сам запрос `quote` ничего не оплачивает. Фактический минимум пополнения определяет Venice; при проверке 17 сентября 2026 он составлял 5 USDC.

Котировка показывает сумму, сеть, mint, кошелёк плательщика, получателя, fee payer, срок действия и `approvalHash`. После **явного одобрения этих условий** запускается:

```sh
npm start -- pay --quote QUOTE_ID --approve FULL_QUOTE_HASH
```

Замените `QUOTE_ID` и `FULL_QUOTE_HASH` значениями из одобренной котировки. Не автоматизируйте передачу хеша из `quote` прямо в `pay`: хеш связывает решение с условиями, но сам по себе не доказывает согласие человека. В будущем шлюзе его выдача должна следовать реальному подтверждению пользователя.

Котировка действует пять минут. Перед подписью условия повторно запрашиваются у Venice и сравниваются без изменения регистра адресов. Новая сумма, получатель, сеть, mint или fee payer требуют новой котировки и нового одобрения. Прототип ограничивает одно пополнение 50 USDC. Оплату комиссии проводит указанный Venice fee payer; клиент отказывается от схемы, в которой fee payer совпадает с покупателем.

После пополнения:

```sh
npm start -- balance
npm start -- models
npm start -- chat --model MODEL_ID --message "Reply briefly: hello from Solana." --max-tokens 64
```

Выберите `MODEL_ID` из актуального списка. `chat` расходует существующий баланс Venice, требует явного вызова и **не пополняет его автоматически**. `max-tokens` ограничивает выход модели, но не является денежным лимитом всей генерации. Перед реальным запросом выбирайте модель с понятной стоимостью. Денежные дневные лимиты и Telegram-подтверждение будут добавлены на этапе интеграции с SingIt.

## Если ответ об оплате потерян

Клиент записывает попытку **до отправки**. Повторный `pay` для того же ордера запрещён, а неопределённый платёж блокирует следующие пополнения этого кошелька даже после перезапуска.

```sh
npm start -- status --quote QUOTE_ID
npm start -- history
npm start -- reconcile --quote QUOTE_ID --transaction SOLANA_TRANSACTION_SIGNATURE
```

Если подпись уже получена от Venice, `--transaction` можно опустить. `reconcile` ничего не отправляет: он читает транзакцию из Solana RPC и сверяет хеш **всего сообщения транзакции** с локально подписанным платежом. Чужая транзакция не снимет блокировку. Статус `confirmed` означает подтверждение платежа в сети; текущий баланс Venice показывается отдельно и не подменяется этим статусом.

При неизвестном результате не удаляйте `.local/`, записи SQLite и не создавайте новую попытку в другом каталоге. Если транзакция не найдена, нужна ручная сверка с Venice. Прототип намеренно не снимает неопределённость по таймауту и не реализует автоматические возвраты.

## Хранение и границы первого этапа

- `.local/` содержит приватный кошелёк и SQLite-журнал публичных условий платежей. Каталог игнорируется Git. Ключ хранится локально в **незашифрованном** формате Solana с правами `0600`; это кошелёк прототипа, не хранилище для пользователей сервиса.
- Подписанные платёжные payload и заголовки авторизации не записываются в журнал и не печатаются при ошибках.
- Платёжный URL фиксирован на `api.venice.ai`; HTTP-перенаправления запрещены.
- Никаких PayAI, собственного платного endpoint, Jupiter, покупки акций, Bitrefill, автопополнений или изменений Telegram-бота в этом этапе нет.
- Библиотечные классы экспортированы из `src/index.mjs` для будущего адаптера шлюза.

## Проверки

`npm test` выполняет локальные проверки без реальных платежей. Сквозной тест использует настоящий Solana SDK и проверяет обе подписи транзакции, но RPC и Venice заменены локальными ответами в памяти.
